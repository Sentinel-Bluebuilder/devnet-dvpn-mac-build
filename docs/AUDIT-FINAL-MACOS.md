# Final audit: the macOS platform layer (#33, rc.8)

Read-only, line by line, by AC-MAC-4 (#38) on 2026-11-20, at #33 main `4ecdb69f9`. Nothing was run: each finding
comes from reading the code, and the ones marked **check** need a guest or runner run before they are called bugs.

Scope: the root steps (`resources/scripts/*`: launchd service, pf kill switch, DNS, socket ACL), the Keychain
(`src/cli/keystore.ts`), launchd state (`src/core/daemon/darwin-launchd.ts`, `src/main/daemon/launchd-state.ts`),
utun/rival-VPN detection (`src/main/system/tunnels.ts`), proxy (`src/main/system/proxy.ts`), the darwin `next`
lines, and the macOS rows in the hub (`Desktop/sentinel-agent-connect-solana`: AGENTS.md, docs/CODES.md,
docs/TROUBLESHOOTING.md, docs/INSTALL-BY-HAND.md).

Severity: **high** = a user is left without network or with a wrong safety claim; **medium** = a wrong result or a
silent failure with a way out; **low** = defence in depth or a rare path; **nit** = wording or a stale comment.

The root steps run as root and are reached only through `dvpn-helper`, via `osascript … with administrator
privileges` or `sudo -n`. The caller is therefore already an administrator, which is why the path findings below
are rated **low** and not higher.

## Checked and clean
- `dvpn-helper`: whitelist of 7 steps, root check, `PATH=/usr/bin:/bin:/usr/sbin:/sbin`, Apple `/bin/bash`, no shell strings.
- `_lib.sh` `parse_args`: names `^[A-Za-z]+$` only; `printf -v` (no eval). `atomic_write` keeps owner, mode and ACL.
- LaunchDaemon (setup-daemon.sh:135-159): root-owned PATH, our own copies only, `plutil -lint`, root:wheel 0644, atomic `mv`, Umask 077, ThrottleInterval 60. The pre-cb33 label is booted out and its plist removed.
- pf: never `-F all`, `-d` or `-f /etc/pf.conf`; the enable token is released with `-X <token>` after the flush, and the token is checked as digits only.
- Keychain (`keystore.ts`): the secret goes as hex on `security -i` stdin (not in `ps`); quotes/newlines refused; the save is read back; locked Keychain = exit 36/51 mapped to one sentence; key files are read-only.
- launchd state: `print` exit 113 = booted out, so `bootstrap`; loaded + not running, so `kickstart -k`; root-only doctor rows are shown as "not checked" while the service does not run.
- tunnels/rival VPN: only `dvpn-c0` and our binary paths are touched; scoped (`I`) routes are ignored; routes are read only while none of ours is up.
- Proxy: a backup is written before the change; our own leftover is never saved as "what the user had"; restore only where the setting is still ours (uninstall-cleanup.sh:109 too).
- darwin `next` lines: `sudo sntp -sS time.apple.com` (agent-cmd.ts:173, daemon-cmd.ts:15), `sudo launchctl bootstrap system /Library/LaunchDaemons/co.sentinel.sentinel-dvpnd.c0.plist` / `kickstart -k system/co.sentinel.sentinel-dvpnd.c0` (darwin-launchd.ts:141, no spaces in either), `chmod 600 <file>`: each is one runnable command.
- Hub rows: CODES `keyfile-mode` and `daemon-missing`, TROUBLESHOOTING:25/:63/:65 (locked Keychain over SSH → key file), AGENTS:35 (Path B "Linux only today"), AGENTS:326-328 (Homebrew drivers, waiting for network) all match the code.
